# Contributing to GamUX

Thank you for your interest in GamUX.

## Development guidelines

1. Keep changes focused on one component.
2. Document dependencies and build requirements.
3. Do not commit generated build artifacts.
4. Never commit passwords, tokens or private credentials.
5. Test changes in QEMU whenever possible.
6. Report hardware-specific compatibility issues.
7. Preserve third-party licenses and notices.

## Branches

- `main`: primary project branch.
- `dev`: integration branch when introduced.
- `feature/name`: new functionality.
- `fix/name`: bug fixes.
- `docs/name`: documentation changes.

## Commit message prefixes

- `feat:` new functionality.
- `fix:` bug fix.
- `docs:` documentation.
- `build:` build system.
- `test:` testing.
- `refactor:` code restructuring.
- `perf:` performance optimization.
- `chore:` maintenance.

Example:

`docs: document initial system architecture`
